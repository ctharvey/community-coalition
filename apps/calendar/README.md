# Community Calendar proof of concept

This is a **non-production** vertical slice for Priority 1, intentionally separate from Hylo and all payment/volunteer systems. It does **not** indicate that Brookfield, any PTO, PfISD or Northtown MUD has agreed to participate.

## Run

Requires Node.js 22 or newer.

```bash
cd apps/calendar
npm install
npm test
npm run build
npx serve public
```

Open the address printed by the static file server. Do not deploy the draft without a review of its privacy, authorization, security and license choices.

## Data sources

- `data/sources.json`: candidate organizations. None are enabled by default. Before enabling an ICS entry, obtain the actual **public** ICS URL, verify it contains no private events, get appropriate organizational approval, set `status` to `active`, `verifiedPublic` to `true`, and set `allowedHosts` to the hostname of the approved HTTPS feed.
- `data/approved-events.json`: curator-approved **public** event records, initially empty. Records marked `draft` or nonpublic will never be published by the build.
- `public/events.json`: generated static snapshot. The public page reads this file without login.

Example curated entry (illustrative only; don't publish without genuine approval):

```json
{
  "id": "example-approved-event",
  "status": "approved",
  "visibility": "public",
  "organization": "Example Organization",
  "title": "Example Neighborhood Gathering",
  "start": "2026-11-07T15:00:00Z",
  "end": "2026-11-07T17:00:00Z",
  "location": "Example Park",
  "sourceUrl": "https://example.org/event"
}
```

## Current boundaries and unfinished work

The build imports only explicitly approved HTTPS feeds; there is no untrusted user-facing feed creation. If any active feed fails, it exits unsuccessfully **before replacing** the last good published snapshot. It normalizes recurring events and cancelled instances, keeps source attribution and renders a responsive public listing.

This is **not a public launch**. Remaining gates:

1. Validate two real independent sources and obtain partner approval; check that feeds contain public events only.
2. Verify timezone/all-day and recurrence behavior against the real feeds, including reschedules, cancellations and updates.
3. Add per-source health history, change-detection alerts and cautious cross-source duplicate review. Current duplicate handling is only within each canonical source/occurrence.
4. Secure remote fetching against DNS rebinding/private-IP resolution (the prototype is restricted to operator-committed URLs; production needs an SSRF-safe fetcher).

## Why this split?

The Apache-2.0 [Community Calendar](https://github.com/judell/community-calendar) project informed the source registry and curator pattern. It is a strong upstream candidate, but its complete pipeline includes Python, Supabase and XMLUI. We are prototyping a smaller Apache-2.0 [node-ical](https://github.com/jens-maus/node-ical)-powered ingestion first and will reassess upstream code reuse after real-source tests. No upstream source code has been copied.

## Local flyer intake demonstration

Run `npm run demo` and open the printed loopback address. Use synthetic material only. In mock mode, the browser accepts a PNG, JPEG or PDF up to 5 MB and checks its signature, then generates fixed mock fields; it does not inspect or extract the file. A source link is optional attribution. Provide a synthetic file, direct image link, or pasted text for extraction; mock mode also accepts a source link alone. Review and edit each field; add another draft for a flyer with multiple events. Date and both times must be supplied before confirmation. Confirmation is local and does not submit, approve, or publish. Successful OpenAI extractions save the original file and extracted fields under `.local-review/`, outside the public site. Edits in the browser are not yet saved. Mock drafts disappear on reload. OpenAI modes send supplied content through the local server to OpenAI. The public calendar remains independent.

This local demo has **no authentication, organization authority, durable storage, malware scanning, privacy classification, production extraction, submission, approval, publishing, or event edit/cancel workflow**. File signatures are only a basic format check and do not establish safety. Do not expose the demo server to a network or use real participant data. A production design needs authenticated organization-scoped storage and review, CSRF and upload defenses, a retention policy, and verified organizer authority. The simple same-day time validation does not resolve DST gaps or repeated times; these need explicit review in a production workflow.

Mock mode uses no external service or credentials. The OpenAI extraction returns drafts with title, description, organization, date, start and end times, time zone, venue, admission, source URL and unknowns. GPT-6 Luna with standard processing is the demo default; Flex is an explicit test option. Production use still requires provider and privacy approval. A public Facebook URL may require an attached flyer; no scraping or Facebook publication is implemented. Storage and hosting remain open decisions: local review files do not provide authenticated multi-user access.

### Local OpenAI extraction test

Set `OPENAI_API_KEY` in the demo server environment, then run `npm run demo`. Choose GPT-6 Luna standard processing (or explicitly choose Flex) and supply a synthetic image/PDF, a direct public HTTPS image link, or pasted synthetic text. The server sends this content or image link to OpenAI using `gpt-6-luna` (override with `OPENAI_MODEL`), the selected processing tier and structured output; the API key stays on the server. Requests can take several minutes and incur API charges. A direct image link must return a public PNG or JPEG without redirects; the server downloads it with a 5 MB limit, saves it, and sends its bytes to OpenAI. The prototype requires public IPv4 DNS answers and pins the connection to a checked address. It is distinct from the optional event source link, which is attribution and is never fetched. A Facebook post URL is not a direct image link. If a flyer gives a month and day without a year, the app chooses the next occurrence in Chicago, matching a stated weekday when present, and flags the assumed year for review. Explicit years are preserved and weekday conflicts flagged. An old flyer can still be assigned a future date, so verify the source is current. Review all generated fields and uncertainty notes before confirming. Nothing is published; successful extraction results and original files are retained locally until manually deleted.

The localhost service is a demonstration, not authenticated production infrastructure. Use only synthetic content, and do not expose it to a network. Review files have no automatic expiry, authentication, or encryption; OS access controls apply. The API request sets `store: false`; that setting does not itself establish a complete retention policy.

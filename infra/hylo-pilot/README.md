# Self-hosted Hylo pilot

This is an experimental, isolated development pilot, not a production deployment. It uses a separate PostGIS database container and volume, Redis, Hylo backend and web containers. Web and API ports are bound to the Docker host's loopback; the database and Redis publish no ports. Do not enter real participant data or configure live external-service credentials. Local review, authorization, privacy, backups, and security still need a production design.

## Reproduce the pilot

1. Clone `https://github.com/Hylozoic/hylo` into a separate, disposable source checkout and check out revision `c141ceec71dae2db9f84c36ccae6bab5fd37e943` (upstream `dev`). **Use a clean checkout without local credentials, `.env` files, or other private files:** the build currently copies its source context into the image. Do not reuse an existing development checkout with secrets. This pinned source has not been modified by the pilot.
2. Configure Docker to use the intended test host. From the community-coalition repository, run `node infra/hylo-pilot/configure.mjs <absolute-Hylo-checkout-path>`. This generates a private `.env` with the paths and new pilot-only secrets and refuses to overwrite an existing configuration. Restrict access to that file; it is Git-ignored. On Windows, OS access controls govern the file; the Node mode setting alone does not establish a restrictive Windows ACL.
3. From `infra/hylo-pilot`, run `docker compose build`, then `docker compose up --no-build -d --wait database redis`. This creates a dedicated database volume. On an SSH Docker context the SQL schema is packaged into the database image, not bind-mounted from Windows.
4. On a **new, empty, disposable pilot database only**, run `./seed.ps1 -ConfirmEmptyPilot` in PowerShell. The script checks that the seeded tables are empty before invoking Hylo's destructive starter seed. The pinned upstream seed writes a nonexistent `groups_posts.active` column; this pilot removes that field in a temporary seed container only. Upstream's migration seed records migration files as applied; it does not itself prove the schema includes every change. Do not run this seed against existing data.
5. Run `docker compose up --no-build -d backend web`. When Docker is on the desk-side server, create a private tunnel from the browser computer: `ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:3330:127.0.0.1:3330 -L 127.0.0.1:3101:127.0.0.1:3101 ubuntu-server`. Then open `http://localhost:3330/`. Keep the tunnel running; these addresses use HTTP and must not be publicly exposed.

The separate Node 24 Dockerfile replaces an obsolete upstream web Dockerfile that targets Node 8. The focused build includes the upstream root workspace for test types. The web container applies a local Vite proxy adjustment for internal routing and the localhost OIDC issuer; this is not a general custom-domain solution. The upstream backend requires a Stripe key at startup, so the pilot supplies a deliberately invalid placeholder. Third-party login placeholders are invalid; Segment analytics, email and push are disabled. Payments, external logins, and uploads are not configured.

## Checkpoint, 2026-10-26

- Hylo web and backend, PostGIS 18 and Redis started on `ubuntu-server`; local web and GraphQL requests returned HTTP 200 through the SSH tunnel, and the Hylo sign-in page rendered in a browser. OIDC discovery and JWKS respond with localhost URLs after the Vite proxy adjustment.
- `verify-login.cjs`, copied into the backend container and run there, created synthetic users. Password login, a wrong-password rejection, session identity, logout, CORS, and a second user's denial when attempting to edit the first user's private group passed. This is one authorization check, not proof of complete tenant isolation.
- A test `pg_dump` was restored into a separate database within the pilot container; the synthetic user and group counts matched. The temporary dump in the container is not a backup strategy: no external backup location, schedule, retention, encryption, or disaster recovery is configured.
- OIDC authorization-code sign-in and calendar integration, role revocation, real organizer enrollment, custom-domain HTTPS, complete migrations, worker jobs, uploads, and production security were not verified. The app has not been deployed publicly.
- Two earlier pilot volumes remain from a failed PostgreSQL 17 schema initialization and a partially seeded PostgreSQL 18 attempt; they have not been deleted. The active volume is `community-hylo-pilot_hylo-db-v3`. The current tunnel and containers are separate running processes and can stop independently.

Do not remove volumes without a deliberate data-retention decision. `docker compose down` without `--volumes` preserves the database; avoid running upstream destructive seeds against a database containing user data.
